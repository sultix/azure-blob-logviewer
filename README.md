# azure-blob-logviewer

A desktop application for exploring and reviewing log artifacts stored in Azure
Blob Storage. Built with **Wails v2**, **Go**, **Angular 20** (standalone +
signals), **Tailwind CSS**, **PrimeNG**, and **Vitest**.

See [AGENTS.md](./AGENTS.md) for the engineering rules that govern this
repository.

## Prerequisites

- Go (latest stable, 1.24+)
- Node.js 20+
- Wails CLI: `go install github.com/wailsapp/wails/v2/cmd/wails@latest`

## Common commands

From the repository root:

```bash
# Run the desktop app with hot reload (Wails dev server)
wails dev

# Produce a production desktop build
wails build
```

Inside `frontend/`:

```bash
npm install
npm run icons    # Regenerate app icons from /icons
npm run start    # Angular dev server (browser only)
npm run build    # Production Angular build
npm run test     # Vitest unit tests
npm run lint     # ESLint (Angular + TypeScript + templates)
```

## Notes

- The Wails bridge bindings are generated by `wails dev` / `wails generate module`
  into `frontend/wailsjs/` and are git-ignored. The `AppApiService` in
  `frontend/src/app/core/services/app-api.service.ts` wraps the generated
  bridge behind a typed interface.
- Keep `frontend/dist/` under version control only via the `.gitkeep` stubs so
  the `go:embed` directive in `main.go` compiles before the first frontend
  build.
- `icons/macos/1024x1024.png` is the single source of truth for app icons.
  All desktop and frontend branding assets are regenerated from it via
  `frontend/scripts/generate-icons.mjs`.
- `npm run icons` refreshes `icons/icon.png`, the platform icon sets,
  `frontend/src/assets/branding/*`, `frontend/src/favicon.ico`, and
  `build/appicon.png`.
- `wails dev` and `wails build` run the same icon generator automatically via
  `preBuildHooks`, so frontend branding and Wails build inputs stay in sync.

## Build a Windows client

```bash
wails build -platform windows/amd64 -clean
```

The resulting executable is written to:
[build/bin/azure-blob-logviewer.exe](build/bin/azure-blob-logviewer.exe)

This is the correct build path for this repository because
[wails.json](./wails.json) already wires up `npm install` and `npm run build`
for the frontend. The prerequisites are Go `1.24+`, Node `20+`, and the Wails
CLI:

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

The Windows EXE icon is regenerated from the icon master during the build, so
no manual icon copy step is required.

Optional:

- Generate an installer instead of only a `.exe`:
  `wails build -platform windows/amd64 -clean -nsis`
- Use a custom output name:
  `wails build -platform windows/amd64 -clean -o logviewer`
- Build for Windows on ARM:
  `wails build -platform windows/arm64 -clean`
